## 1. Deal Statuses

| Status | Meaning |
|--------|---------|
| `CREATED` | Seller created the deal; awaiting buyer funding |
| `FUNDED` | Buyer has "paid" (fake UPI); seller must deliver |
| `DELIVERED` | Seller provided delivery proof; buyer must accept or dispute |
| `COMPLETED` | Buyer accepted; money released to seller (terminal) |
| `DISPUTED` | Buyer raised dispute; AI verdict generated; admin must resolve |
| `RESOLVED_RELEASED` | Admin resolved → release full amount to seller (terminal) |
| `RESOLVED_REFUNDED` | Admin resolved → refund full amount to buyer (terminal) |
| `RESOLVED_SPLIT` | Admin resolved → split per `sellerSharePercent` (terminal) |

**Valid transitions** (any other → 409):
```
CREATED → FUNDED
FUNDED → DELIVERED
DELIVERED → COMPLETED
DELIVERED → DISPUTED
DISPUTED → RESOLVED_RELEASED | RESOLVED_REFUNDED | RESOLVED_SPLIT
```

## 2. Deal JSON (camelCase — frontend sees this)

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | UUID v4 |
| `title` | string | Required, 1–200 chars |
| `description` | string | Required, 1–2000 chars |
| `amount` | integer | **Integer rupees** (paise not used), > 0 |
| `status` | string | One of the 8 statuses above |
| `sellerName` | string | From `x-user-name` header on create |
| `buyerName` | string \| null | Null until `FUNDED`; set on fund |
| `deliveryProof` | string \| null | Set on `deliver` |
| `disputeReason` | string \| null | Set on `dispute` |
| `aiVerdict` | object \| null | See below; set on `dispute` |
| `createdAt` | string | ISO 8601 UTC, e.g. `2026-01-15T10:30:00.000Z` |

### `aiVerdict` shape (when not null)

```json
{
  "recommendation": "RELEASE" | "REFUND" | "SPLIT",
  "sellerSharePercent": 0-100,
  "confidence": "LOW" | "MEDIUM" | "HIGH",
  "reasoning": "string (2-4 sentences)"
}
```

**Consistency rules** (enforced by AI, re-validated by admin resolve):
- `RELEASE` → `sellerSharePercent == 100`
- `REFUND` → `sellerSharePercent == 0`
- `SPLIT` → `1 <= sellerSharePercent <= 99`

## 3. Event JSON (camelCase — frontend sees this)

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | UUID v4 |
| `dealId` | string | FK to deal |
| `type` | string | One of: `CREATED`, `FUNDED`, `DELIVERED`, `COMPLETED`, `DISPUTED`, `RESOLVED_RELEASED`, `RESOLVED_REFUNDED`, `RESOLVED_SPLIT` |
| `fromStatus` | string | Status before this event |
| `toStatus` | string | Status after this event |
| `actorRole` | string | `seller` \| `buyer` \| `admin` |
| `actorName` | string | From `x-user-name` header |
| `note` | string | Human-readable: `"Deal created"`, `"Funded by Alice"`, `"Delivered: <proof>"`, `"Accepted by Bob"`, `"Disputed: <reason>"`, `"Resolved: RELEASE by admin"` |
| `fromStatus` / `toStatus` | string | For `CREATED` event: both `CREATED`; for others: actual from/to statuses |
| `createdAt` | string | ISO 8601 UTC |

**Ordering**: Events returned oldest-first (`createdAt ASC`).

## 4. PostgreSQL Schema (snake_case — internal)

### `deals` table

```sql
CREATE TABLE deals (
  id           UUID PRIMARY KEY,
  title        TEXT NOT NULL,
  description  TEXT NOT NULL,
  amount       INTEGER NOT NULL CHECK (amount > 0),
  status       TEXT NOT NULL CHECK (status IN (
    'CREATED','FUNDED','DELIVERED','COMPLETED',
    'DISPUTED','RESOLVED_RELEASED','RESOLVED_REFUNDED','RESOLVED_SPLIT'
  )),
  seller_name  TEXT NOT NULL,
  buyer_name   TEXT,                       -- NULL until FUNDED
  delivery_proof TEXT,                     -- NULL until DELIVERED
  dispute_reason TEXT,                     -- NULL until DISPUTED
  ai_verdict   JSONB,                      -- JSONB of aiVerdict, NULL otherwise
  created_at   TIMESTAMPTZ NOT NULL        -- ISO 8601 UTC
);
```

### `events` table

```sql
CREATE TABLE events (
  id           UUID PRIMARY KEY,
  deal_id      UUID NOT NULL REFERENCES deals(id),
  type         TEXT NOT NULL CHECK (type IN (
    'CREATED','FUNDED','DELIVERED','COMPLETED',
    'DISPUTED','RESOLVED_RELEASED','RESOLVED_REFUNDED','RESOLVED_SPLIT'
  )),
  from_status  TEXT NOT NULL,
  to_status    TEXT NOT NULL,
  actor_role   TEXT NOT NULL CHECK (actor_role IN ('seller','buyer','admin')),
  actor_name   TEXT NOT NULL,
  note         TEXT NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL,       -- ISO 8601 UTC
  FOREIGN KEY (deal_id) REFERENCES deals(id)
);
```

**Initial CREATED event**: `from_status = 'CREATED'`, `to_status = 'CREATED'` (not NULL). This applies to both `seed.py` and `POST /api/deals`.

> **Note**: UUIDs generated by application (Python `uuid.uuid4()`), not DB. `ai_verdict` uses `JSONB` for efficient querying. Timestamps are `TIMESTAMPTZ` (stored as UTC).

## 5. Auth (Demo Only)

Every request **must** include:
- `x-user-role`: `seller` \| `buyer` \| `admin`
- `x-user-name`: arbitrary string (e.g., `"alice"`, `"bob"`, `"admin1"`)

No tokens, no sessions, no password checks. Role determines authorization:
- `seller`: can create deals, deliver on own deals
- `buyer`: can fund `CREATED` deals, accept/dispute on own funded deals
- `admin`: can resolve `DISPUTED` deals, sees all deals

Missing/invalid role → `403 { "error": { "code": "FORBIDDEN", "message": "..." } }`

## 6. Error Format

All errors (400, 403, 404, 409) return:

```json
{
  "error": {
    "code": "STRING_CODE",
    "message": "Human-readable explanation"
  }
}
```

| HTTP | Code | When |
|------|------|------|
| 400 | `VALIDATION_ERROR` | Missing/invalid fields, amount ≤ 0, non-integer amount, malformed JSON |
| 403 | `FORBIDDEN` | Wrong role for action, not the deal's seller/buyer |
| 404 | `NOT_FOUND` | Deal ID doesn't exist |
| 409 | `INVALID_TRANSITION` | Status not in expected state for this action (e.g., fund twice, deliver before fund) |

> **Note**: FastAPI defaults to 422 for validation. Backend overrides to 400 with this format.

## 7. Routes

### Common
- All `POST` bodies: `Content-Type: application/json`
- All responses: `application/json`
- All timestamps: ISO 8601 UTC (`YYYY-MM-DDTHH:mm:ss.sssZ`)

---

### `POST /api/deals` — Create deal (seller)

**Headers**: `x-user-role: seller`, `x-user-name: <name>`

**Request**:
```json
{
  "title": "Logo design for startup",
  "description": "Modern minimalist logo, 3 revisions included",
  "amount": 15000
}
```

**Response 201** — Deal object (status `CREATED`, `buyerName: null`, `deliveryProof: null`, `disputeReason: null`, `aiVerdict: null`)

**Event created**: `type=CREATED`, `fromStatus=CREATED`, `toStatus=CREATED`, `actorRole=seller`, `actorName=<x-user-name>`, `note="Deal created"`

**Errors**: 400 `VALIDATION_ERROR`, 403 `FORBIDDEN` (if not seller)

---

### `GET /api/deals` — List deals

**Headers**: `x-user-role`, `x-user-name`

**Response 200** — Array of deals, **newest first** (`createdAt DESC`)

**Visibility**:
- `seller`: only own deals (`seller_name = x-user-name`)
- `buyer`: `CREATED` deals (all) + own deals (where `buyer_name = x-user-name`)
- `admin`: all deals

---

### `GET /api/deals/:id` — Get deal + events

**Headers**: `x-user-role`, `x-user-name`

**Response 200**:
```json
{
  "deal": { ...deal object... },
  "events": [ ...events oldest-first... ]
}
```

**Errors**: 404 `NOT_FOUND`

---

### `POST /api/deals/:id/fund` — Buyer funds deal (CREATED → FUNDED)

**Headers**: `x-user-role: buyer`, `x-user-name: <buyerName>`

**Request**: `{}` (empty body)

**Response 200** — Updated deal (status `FUNDED`, `buyerName` set)

**Errors**: 403 `FORBIDDEN` (not buyer), 404 `NOT_FOUND`, 409 `INVALID_TRANSITION` (not `CREATED` or already funded)

---

### `POST /api/deals/:id/deliver` — Seller delivers (FUNDED → DELIVERED)

**Headers**: `x-user-role: seller`, `x-user-name: <must match deal.sellerName>`

**Request**:
```json
{ "deliveryProof": "Figma link: https://figma.com/... + PNG exports attached" }
```

**Response 200** — Updated deal (status `DELIVERED`, `deliveryProof` set)

**Errors**: 400 `VALIDATION_ERROR` (missing deliveryProof), 403 `FORBIDDEN` (not the deal's seller), 404 `NOT_FOUND`, 409 `INVALID_TRANSITION` (not `FUNDED`)

---

### `POST /api/deals/:id/accept` — Buyer accepts (DELIVERED → COMPLETED)

**Headers**: `x-user-role: buyer`, `x-user-name: <must match deal.buyerName>`

**Request**: `{}`

**Response 200** — Updated deal (status `COMPLETED`)

**Errors**: 403 `FORBIDDEN` (not the deal's buyer), 404 `NOT_FOUND`, 409 `INVALID_TRANSITION` (not `DELIVERED`)

---

### `POST /api/deals/:id/dispute` — Buyer disputes (DELIVERED → DISPUTED)

**Headers**: `x-user-role: buyer`, `x-user-name: <must match deal.buyerName>`

**Request**:
```json
{ "disputeReason": "Delivered logo doesn't match brief; missing source files" }
```

**Response 200** — Updated deal (status `DISPUTED`, `disputeReason` set, `aiVerdict` set or `null`)

**Behavior**: Calls `ai.get_ai_verdict(deal)`. **Must succeed even if AI returns `None`** (deal still becomes `DISPUTED`, `aiVerdict` stays `null`).

**Errors**: 400 `VALIDATION_ERROR` (missing disputeReason), 403 `FORBIDDEN`, 404 `NOT_FOUND`, 409 `INVALID_TRANSITION` (not `DELIVERED`)

---

### `POST /api/deals/:id/resolve` — Admin resolves (DISPUTED → RESOLVED_*)

**Headers**: `x-user-role: admin`, `x-user-name: <adminName>`

**Request**:
```json
{ "outcome": "RELEASE" }  // or "REFUND" or "SPLIT"
```

**Response 200** — Updated deal (status `RESOLVED_RELEASED` | `RESOLVED_REFUNDED` | `RESOLVED_SPLIT`)

**If `SPLIT`**: Uses `deal.aiVerdict.sellerSharePercent` (must exist and be 1–99). If missing/invalid → 400.

**Errors**: 400 `VALIDATION_ERROR` (invalid outcome, SPLIT without valid aiVerdict), 403 `FORBIDDEN` (not admin), 404 `NOT_FOUND`, 409 `INVALID_TRANSITION` (not `DISPUTED`)

---

**Response 200**: `{ "ok": true, "dealsCreated": 5 }`

**Errors**: 403 `FORBIDDEN` if `ALLOW_SEED != "true"`

## 9. Transactional Guarantees (Backend Must Enforce)

- **Status update + event insert = ONE transaction** (atomic)
- **Conditional update**: `UPDATE deals SET status = ? WHERE id = ? AND status = ?` (or equivalent) to prevent double-submit races
- **Integer money**: `amount` stored as integer rupees, never float
- **Event on every status change**: exactly one event row per transition

## 10. Resolved Ambiguities (Confirmed)

All points confirmed as written:
1. **Deal ID**: Backend generates UUID v4.
2. **`x-user-name`**: Treated as opaque string, no uniqueness enforced.
3. **`SPLIT` resolve**: Requires valid `aiVerdict` with `1 <= sellerSharePercent <= 99`; else 400.
4. **Concurrency**: Conditional `UPDATE ... WHERE status = ?` handles double-submit.
5. **Timestamps**: Millisecond-precision ISO 8601 UTC (`YYYY-MM-DDTHH:mm:ss.sssZ`).
6. **Null handling**: JSON `null` → SQLite `NULL` for optional fields.

**Additional**: Initial `CREATED` event has `from_status = 'CREATED'`, `to_status = 'CREATED'` (not NULL).
